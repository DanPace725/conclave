# Automatic conversation memory

Context and Agent mode capture conversation-local user commitments and corrections before answering. The append-only ledger is separate from context snapshots: restoring or compacting a working snapshot cannot undo a correction or suppression. Ordinary browser Chat does not use this ledger.

## Capture and authority

Memory policy v7 offers substantive human discussion as unresolved candidate data (at least 160 characters and 16 meaningful distinct words). Otherwise a following non-acknowledgment turn can offer the previous completed substantive assistant discussion (320 characters / 24 meaningful words), without requiring research tools. Explicit memory-saving requests and three original-source/file reads also qualify. Current human discussion has priority. One source can use optional selection per turn; direct Jev selection is capped at two calls, with unassessed/oversized/uncertain passage IDs recorded. Partial or suppressed assistant output is excluded. Short acknowledgments do not themselves trigger optional selection. Explicit commitments/corrections still use the deterministic path.

Code offers complete paragraphs, each at most 8,000 characters. A human paragraph containing a quotation can be selected as unresolved data when it contains at least 40 unquoted non-whitespace characters; quote-only instruction material cannot create a commitment. Complete selected paragraphs retain quoted qualifications and exact UTF-16 spans. Capture receipts and local eligibility checks distinguish passages considered from actual provider calls. Assistant ideas remain model-proposed, not accepted decisions. Selection does not rewrite canonical history.

## Working representations and engagement

Automatic memories use full text, up to four pointers under a separate 1,200-byte ceiling (also capped at 15% of the full-memory allowance), or a searchable archive outside the prompt. Meaningful whole-word matches replace substring counts. Multi-word queries require two meaningful overlaps for lexical admission; accepted semantic similarity of at least 0.45 admits full text, 0.3–0.45 a pointer. These are initial heuristics, not calibrated probabilities. Acknowledgments reuse a bounded recent human query. Binding scoped requirements and dependency/conflict closure bypass relevance. Full-memory capacity still fails explicitly rather than silently dropping binding requirements.

Named evidence/questions also have a bounded optional projection and pointers; canonical named state stays unchanged/protected. Objectives, constraints, decisions, pins and exact-text requirements remain fully represented with their named dependencies. Named records participate in persistent semantic indexing. `retrieve_memory` reads one current automatic/named entry with revision checks and exact pagination, avoiding collection-wide inspection for a known pointer. Fetch dependencies before relying on partial text.

Substantive human returns can record inferred engagement, deduplicated by query hash. Prompt inclusion and assistant echoes do not count. The retrieval-order boost is capped at 0.1 and halves every 30 days; it cannot admit an irrelevant record or change authority/confidence/lifecycle. Retention metadata records the selecting policy/source and whether its rationale is an inference, with source/scope/dependency/intent changes as reconsideration conditions. Relationship learning and semantic thresholds still need live evaluation.

## Reviewable suppression proposals

`propose_memory_suppression` records 1–8 exact targets, snippets and fingerprints under a readable key without suppressing anything. A current human request explicitly approving that key can use `suppress_memory` with `proposal_key`; it must target the exact unchanged set and current revisions. Direct target approval still works. Workspace can show the same IDs/snippets and approve the saved set through `approve_memory_suppression` without inference. Changed targets/proposals, stale revisions, quoted approvals, and pinned/exact-text entries are rejected. Historical snippets remain in canonical human inspection; suppressed text is omitted from model memory reads and earlier proposal receipts are excluded from model lookup.

Explicit instruction clauses such as `Keep it below $500.50.` and `Only use staff with clearance if children attend.` retain their complete exact wording and source spans. A clause is binding when it starts with a directive (keep, do not, never, must, always, only, use, avoid, ensure, remember, the budget is/must/should, we must/will/decided, or I want/need/require/decided/choose/prefer) and contains no tentative or reporting word. So a plain `I prefer weekend workshops.` is captured as a binding `user_committed` record. Clauses with a tentative word (maybe, perhaps, might, could, consider, suppose, what if) are never binding: `Maybe I prefer …` or `maybe $300` become unresolved preferences, and other tentative phrasing is not captured deterministically. Quotes, code blocks and document instructions cannot create binding commitments. This conservative grammar can miss an instruction; the exact current user message remains in the request.

When a message contains a durable-memory cue (budget, preference, constraint, requirement, remember, correction, decided or decision) without an explicit capture, the production service may select one source for candidate extraction. Complete passages are split into at most eight calls, each with four short prior heads, eight candidate spans, 600 output tokens, a 12,000-byte request guard and a 15-second signal. Request overflow defers capture explicitly; at most eight records are committed globally. When task-model extraction or optional comparison is enabled, it uses the selected task model, has no tools, and appears as `memory-extraction` or `memory-comparison` in purpose/usage records. The service default uses Jev instead. Its proposals can only be unresolved preferences/reports/questions. A span check establishes provenance, not semantic entailment or factual truth.

## Active Jev selection and optional comparison

Normal Context/Agent services default to active Jev selection. When Jev is enabled and available, Jev judges the same numbered paragraphs as a `memory-selection` call: one Choice question per complete paragraph (`skip`, `preference`, `claim`, `question`). Paragraphs are never truncated; batches split at 12 questions or the 8,000-byte guard, and a paragraph that cannot fit alone is listed as `oversized`. Code applies the cross-paragraph rules: keep/skip confidence uses the aggregate non-skip probability with a default 0.65 floor; kind uncertainty is recorded separately. Neither side above the floor marks a passage for review; direct Jev mode makes no task-model fallback call. Exact duplicates of up to four related saved memories are dropped, and at most eight are kept by keep probability.

Confident Jev records are committed as unresolved candidates, with separate `memory_selection` and `memory_selection_applied` events. Uncertain/oversized IDs remain visible for review, and Jev failure records a capture issue without invoking the task model. Missing or disabled Jev does not stop deterministic commitment/correction capture. Optional `CONCLAVE_MEMORY_COMPARISON=task-model` (service `memoryComparison: true`) runs the task model after Jev capture, as `memory-comparison`; its `memory_comparison` event has `applied: false`. Disagreement and comparison failures never change Jev's memory. Comparison is disabled by default. Workspace shows these outcomes separately.

`scripts/evaluate-memory-selection.js` scores selectors against hand labels. `prepare EXPORT.json --out labels.json` writes blind label items (completed assistant answers and human turns, numbered as capture numbers them) and, separately, `labels.recorded.json` with any recorded shadow selections. Label each paragraph `skip`, `optional`, `keep`, `preference`, `claim` or `question`. `score labels.json --recorded labels.recorded.json` scores the recorded selections at no cost; `--jev` and `--llm provider:model` run live selectors over the labeled paragraphs and add usage, latency, priced cost and Jev fallback need. Scores measure selection against labels, not factual accuracy, answer quality or whole-task savings.

Library harnesses use deterministic capture by default; enable candidate selection with `memoryModel: true` and choose `memorySelector: 'jev'` for direct Jev testing. Omitting the selector in a standalone harness preserves its previous task-model behavior. Dependency-injected service providers default to deterministic capture unless this option is explicitly enabled. The normal local and hosted services enable it. Extraction reasoning uses the shared model capability table. Failed extraction retains the source and records a failure. Configuration/authentication errors stop automatic retries; transient failures can retry on subsequent Context activity, with at most three total attempts and one source selection shared across retry/new capture. Per-source `capture_issues` persist after unrelated successful captures; the count and bounded last 20 issues include retry disposition. Stop aborts Agent memory calls through the same run signal and token/deadline guards. Completed user captures survive; partial model output is never admitted as a memory.

`user_committed` is an instruction status, not verified external truth. `user_reported`, `model_proposed`, and `externally_reported` remain attributed reports. Confidence stays null. Recalls and paraphrases add no independent support. Model-created named constraints/decisions are unresolved unless they preserve an explicit human instruction. Model state updates cannot replace a binding user constraint with arithmetic or an interpretation.

Opt-in `CONCLAVE_MEMORY_SELECTOR=jev-hybrid` (service option `memorySelector: 'jev-hybrid'`) accepts confident Jev decisions and sends only uncertain/oversized passages to the task model. Jev failure falls back to eligible passages; Stop is not swallowed. Per-record selector/model provenance and proposal/applied telemetry are separate from source authority. Default is `CONCLAVE_MEMORY_SELECTOR=jev`, with no task-model fallback or comparison. `CONCLAVE_MEMORY_SELECTOR=task-model` explicitly restores the older active task-model/Jev-shadow mode. See [active selection evidence](archive/2026-10-05/jev-active-memory.md). See [repair evidence](archive/2026-10-05/jev-plumbing/README.md).

## Explicit requirements and project scope

Policy v6 also captures clear declared budget, expected attendance, audience, duration and station-count fields, and mandatory event/accessibility/offline requirements. Correction headers apply to substantive later clauses rather than correction preambles. Unique unconditional scalar fields can supersede their same-project predecessor; conditional or ambiguous fields are not treated as unconditional replacements. Full source wording remains exact. Routine keep-working/developing instructions and final-plan/audit requests are not durable memory. Explicitly unapproved participant proposals remain unresolved with their cost and lack-of-approval qualifier.

Named projects are recognized only from explicit human planning declarations, return instructions and named correction headers. Labels are data; quoted/fenced declarations cannot establish a project. Corrections and deduplication stay within the project; activation includes that project and existing global binding instructions. Historical nonbinding heads can derive scope from consistent source references; mixed-project heads stay inspectable but are excluded from activation. Existing global binding heads remain global. This does not recapture missing historical facts or infer arbitrary topic changes. See [repair evidence](archive/2026-10-05/conversation-memory-repairs.md).

## Corrections and selection

`Correction: keep it below $700.` replaces a unique head with the same syntactic key. The v2 policy also recognizes `New commitment: budget should be between $400 and $500` and `I actually want to make it a range, between 400 and 500`. A narrow numeric USD-budget matcher preserves named subjects, scope and condition suffixes; a pronoun range can inherit a unique compatible budget slot. Exact complete source text is retained and unspecified endpoints remain unspecified. Multiple compatible heads produce a non-binding conflict candidate, and every head it matched is also marked contested until the user clarifies. A changed value without a correction cue (`Keep it below $500.` then `Keep it below $700.`) does not replace the earlier record: both stay binding and both become contested. There is no general semantic merging or global contest operation: unrelated, differently conditioned or differently named instructions remain eligible. Contested records require clarification before consequential action. The Memory editor can identify/correct the intended record without a model call.

Human quotes, fences and blockquotes are masked consistently before instruction capture and targeting; assistant quotations are eligible unresolved research data. UTF-16 source offsets remain exact. A clause containing quoted conditions is conservatively skipped rather than truncated into an unconditional commitment; the original latest user message remains available.

Binding records, their conflict alternatives and declared dependencies are selected first. Exact repeated human clauses share one head and retain all source spans without gaining independent support; the prompt carries the latest exact span and a source count. Optional unresolved memories use lexical task matching and dependency/conflict closure under the remaining allowance. The automatic-memory allowance is 20% of the request byte guard, bounded to 800–16,000 bytes; the complete provider request still passes the existing guard. Overflow produces an explicit failure rather than silently dropping a commitment. Inspection remains available so the user can correct or suppress records. Selection priority does not measure truth or observed usefulness.

Selected memory appears before the settled working context and recent tail, participates in native-input counts and the Memory request-breakdown category, and stays frozen within tool exchanges. User-message revisions and file version/removal changes invalidate dependent records, including transitive declared dependencies, on replay after restart. Agent-start records are scoped to that objective; a new objective or ordinary Context turn does not activate them. Context records remain scoped to the conversation.

## Inspect and edit

Converse's existing Memory tab shows automatic entries alongside manual named state. Open an entry for authority, resolution, lifecycle, scope, selection status, exact sources and previous versions. Edit appends a new human correction. **Don't use this** suppresses the record and excludes its source passages and source-linked context copies from model lookup/projection. **Use this again** rechecks eligibility. Since one source event can contain several clauses, suppressing a clause also excludes that original whole message from raw model lookup; other eligible memory clauses can still be selected.

Suppression is reversible and is not erasure. Human source inspection, prior replies and canonical exports retain the history. Superseded/invalidated sources are also excluded from ordinary model lookup; human inspection can still recover their originals. Existing manual named state remains editable through its prior API.

The model state tool may retire its own unchanged named entry when the current human request explicitly targets it. Retired named entries remain inspectable but leave the active projection. State receipts expose requested/effective status and adjustment reason, including when a proposed constraint remains unresolved.

`read_memory` reads both stores as JSON in 8,000-character pages, including authority, sources, lifecycle, scope, relations and capture issues. Begin with `offset: 0` and both expected revisions null. Later pages must supply `expected_memory_revision` and `expected_state_revision` from the first page; either revision changing requires restarting at zero. Suppressed, invalidated or superseded automatic records and unavailable named state return metadata without text.

`suppress_memory` accepts both current revisions, the current human `source_event_id`, and 1–8 `{kind: automatic|named, id}` targets (automatic memory ID or named key). Every target must be explicitly authorized by that human request; quoted, historical, reported and document-edit requests cannot authorize suppression. Pinned/verbatim named state requires a human edit. A mixed batch saves automatic suppression and named retirement atomically and returns each effective status. It grants no authority, cannot rewrite/promote/restore automatic memory, and preserves canonical history. Restore an automatic entry through the editor. A later human named-state edit can reintroduce that named entry; working-snapshot restore alone cannot.

Suppression immediately refreshes frozen and signed continuations, including Agent checkpoints. Earlier memory/history/file-read receipts are unavailable through model receipt retrieval; reread eligible canonical sources or current files when needed. This conservative boundary prevents replaying a stale inspection snapshot. Human inspection/export remains complete. Suppression of a clause can exclude its entire source event, including related source-linked copies. Existing unrelated prose summaries without source lineage cannot be guaranteed to disappear.

HTTP mutations are `memory_save` (`memory_id`, `kind`, `content`, `expected_memory_revision`) and `memory_lifecycle` (`memory_id`, `operation: suppress|restore`, `expected_memory_revision`). The service view/export includes `memory.records`, current `entries`, independent `revision`, and latest capture status. SQLite and PostgreSQL persist generic memory events through the existing event envelope and hosted sequence/revision/lease fence; no database migration is required. Public library functions are exported from `src/index.js`.

## Embedding-assisted activation

The service can add semantically relevant non-binding records to activation alongside keyword matches. Binding/dependency/conflict closure, lifecycle, objective scope and source authority remain canonical. Scores never create commitments or identify correction targets. Similarity and query provenance persist in activation records, allowing fresh services to reconstruct the selection without another embedding call. See [embedding contracts and setup](EMBEDDINGS.md) for pgvector migration, bounds, usage and fallback behavior.

## Current limits

A `dormant` lifecycle is excluded from selection but is not assigned anywhere yet. See [Context and memory management](CONTEXT_AND_MEMORY_ALGORITHMS.md) for a code-level walkthrough of capture, commit, selection and the named-state authority gate.

This is capture, lifecycle and activation, with fixed rules. It does not implement episode consolidation, learned controller policies, utility decay, cross-chat memory, semantic correction targeting, unattended workers or resumption packets. Automatic capture currently reads human messages/objectives; the ledger can also validate completed assistant/document reports and declared dependencies through library calls. It does not automatically extract facts from all workspace tools/documents. Agent objective boundaries and explicitly named human projects are recognized; other topic boundaries within one conversation are not inferred.

The fixtures in `test/automatic-memory.test.js` cover authority, conditions/units, corrections, capacity, frozen projections, restart, PostgreSQL, source invalidation, suppression and cancellation. They establish those invariants; live quality, latency and total cost benefit are unmeasured.
