# Saved-conversation reads

Image events project attachment metadata and captions while excluding `image_data` in PostgreSQL. Authenticated `action=image` reads fetch just the requested source and its latest removal marker directly. Pixels remain in canonical history/exports. See [the image contract](IMAGES.md).

`GET /api/conclave?action=transcript&conversation=conv_...` reads the display transcript directly from PostgreSQL. It uses the same authentication and no-store headers as the complete view. A repeatable-read transaction reads the authoritative conversation sequence/revision, selected display events and latest Agent checkpoint. It creates no SQLite store, reads no snapshots/segments and performs no model-input calculation, tokenization, inference or embedding calls.

PostgreSQL projects inference request metadata down to provider/model, generation settings and source links. Response projections retain readable reasoning/narration and usage; opaque material is represented only by availability. The latest checkpoint excludes pending tool exchanges, continuation blocks and protected ID lists. Messages, attachments, revisions, reply links, failures and provider/model provenance share the complete view's transcript builder. Current workspace file names/version IDs preserve direct download links; file text remains in the complete view. Agent state/limits/Stop/Resume remain available; detailed run metrics and file contents load with Workspace.

The existing `view`, mutation and download operations retain the full engine path. Canonical events, snapshots, attachments and native responses are unchanged. No database migration or backfill is required for this first increment. Local SQLite exposes the same response shape through the service.

Set `CONCLAVE_LOAD_DIAGNOSTICS=on` to log aggregate read metrics (`read_path: transcript`, selected event count, database/service time, transferred JSON and response bytes). Logs exclude message content and credentials. Converse records browser Performance measures `saved-chat-load` and `saved-chat-render` on saved selection; these measure fetch/parse and synchronous application work, not first paint. Workspace remains a separate complete-view request.

The [offline profile](archive/2026-10-04/hosting-transcript-profile.json), reproduced with `node scripts/profile-hosting.js --out <file>`, compares a 12-turn fixture. Transcript reads took 16–20 ms and returned 66,861 bytes; complete reads took 158–194 ms and returned 139,900 bytes. Cold complete reads fetched about 976 KB of canonical rows versus about 77 KB of display rows. A warm complete-view cache fetched only empty delta arrays; the transcript path deliberately rereads display rows. These PGlite timings exclude Neon/Vercel/network costs and are not production performance or billing evidence.

Remaining work: bounded transcript pagination and an indexed/materialized display model after measuring large conversations. This query still scans conversation events in PostgreSQL, transfers the complete displayed transcript and attached source text, and can become expensive as history grows. Workspace still rebuilds the engine and polls while visible. It needs an independent current-details read path if measurements justify that work. Any future cache/read model must validate canonical sequence/revision and preserve stale-edit rejection, removal/suppression and Agent lifecycle behavior.
