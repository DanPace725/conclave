# Installed dashboard launch correction

The user installed Conclave on Android and received `{"error":"forbidden"}` on opening it. Production HTTP logs showed repeated `/dashboard/` 403 responses from the phone while the ordinary `/dashboard` browser view and its API reads succeeded. No account identifiers or private packets were needed for diagnosis.

The dashboard rejected every `Sec-Fetch-Site: cross-site` request. Public production replay reproduced the error for a GET document navigation. A real cross-site navigation in the local browser fixture reproduced it on desktop and mobile. The preview had served the shell ahead of the production access middleware; it now routes through the real dashboard and only annotates the HTML with its synthetic-data notice.

The guard now permits GET shell navigations in `navigate` mode with `document` or `empty` destination. Chromium's service-worker `fetch(request)` preserves navigate mode but changes the destination to empty: a second browser regression caught that form after worker activation. The exception covers both `/dashboard` and `/dashboard/`; it cannot access API or asset routes. Foreign Host/Origin checks, account ownership, sign-in, non-navigation cross-site rejection, write refusal and CSP `frame-ancestors 'none'` remain enforced. No worker or manifest change is needed for existing installations. [Fetch Metadata navigation guidance](https://web.dev/articles/fetch-metadata)

Validation includes authenticated/anonymous launch cases, foreign origins, API/resource navigation, frames, ordinary fetches and writes. Browser regression fails with 403 before the correction and passes both initial and worker-controlled navigations afterward. All 20 desktop/mobile dashboard browser cases pass, including offline/reconnect and expired-session handling. Final full engine run passes 377 tests with one optional skip; syntax/resource checks pass. One earlier concurrent full run failed an unrelated periodic-agent review count assertion; that suite passed alone and the final full rerun passed. Navigation HTTP fixtures/release replays use native HTTP because Node fetch overwrites `Sec-Fetch-Mode` with `cors`.

Before publication, live public release replay passed 14 of 16 cases: both launch forms still returned 403 on production `efe2d7a`, while health, account/API restrictions, writes and MCP checks passed. The post-deployment replay must make both launch checks pass without weakening those restrictions.

This is Conclave-only work. Converse is unchanged by this correction. Git publication, Railway deployment and live public replay are separate checks; their final SHA/deployment/check receipt belongs in the hosted progress log. Real Android installed-app reopening remains user acceptance, distinct from local browser and public HTTP checks.
