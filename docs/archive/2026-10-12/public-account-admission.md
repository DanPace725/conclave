# Public verified account admission — October 12, 2026

The user reported Google SSO works for the email configured in Railway but not another email, and asked how to allow anyone to sign in. The standalone identity adapter required membership in `CONCLAVE_ALLOWED_EMAILS` after verified Google/password/code exchange and when reading the signed browser cookie. It explicitly rejected `*`, so changing the variable alone on the earlier deployed version would fail startup.

Implemented exactly `CONCLAVE_ALLOWED_EMAILS=*` as explicit public signup. Address lists retain restricted admission; empty/missing configuration and wildcard/address mixtures fail startup. Email syntax and verified upstream account checks remain mandatory. Every account keeps its own existing Neon user ID, signed cookie and owner-bound handoff repository. This does not open anonymous MCP access, share account data or merge users by email. Switching back to a list blocks new browser sign-in and session use outside that list; existing connected-app grants must be revoked separately.

Added durable per-IP budgets shared across addresses and form methods: ten email-code/recovery sends per hour and sixty verification attempts per hour. Existing account/method and Google-start budgets remain. The deployment's bounded proxy-hop setting is unchanged. Shared networks share the IP budget. Neon delivery/auth limits remain separate.

Login, information, support, privacy and terms pages follow the configured admission mode. The privacy page now explicitly describes Google identity/profile processing, authentication purpose and absence of Gmail/Drive/contacts access. Package onboarding points users to the deployed policy instead of hardcoding invitation-only access. The owned-domain and Google External-audience requirements are documented; Google's current basic-identity exception to Testing restrictions is distinguished from Conclave's separate allowlist.
