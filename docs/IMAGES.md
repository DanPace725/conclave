# Saved image sources

Context `ask` and `agent_start` accept one JPEG/PNG or Markdown attachment. Image input fields: `attachment_id`, `name`, `mime_type` (`image/png` or `image/jpeg`), and canonical base64 `data`. Server limits: 512,000 image bytes and dimensions 1–2048. Signatures, dimensions, filename/type agreement, and SHA-256 are checked. Converse resizes/re-encodes uploads up to 10 MB before sending; saved pixels are that processed image, not the original file. `source_sha256` identifies the selected original file when supplied by the browser; it is client-reported, not independently verified.

Each image has one append-only `image` event. Content is a filename/dimension caption. Metadata contains canonical `image_data`, MIME, dimensions, byte length, attachment ID and hash. Text indexes, Jev, automatic memory, embeddings, transcript responses and context sources use captions/metadata, never encoded pixels. No schema migration or object-storage service is required. Historical image bytes remain in canonical private JSON exports.

The current image is included as native OpenAI `input_image` or Anthropic `image` content. Audits and frozen Agent projections record `conclave-image:<event_id>`; pixels are resolved only at provider/preflight boundaries. The 4 MB transport bound is separate from the request guard. One image is supplied per request. Images offloaded from working context stay searchable; `view_image` accepts an event ID or E handle, changes the selection, and starts a fresh projection/continuation. Selection carries into follow-ups until a new upload or explicit selection changes it.

Revised-message attachments, removed images and suppressed sources are excluded from ordinary model access; history remains exact. Editing an image-bearing message can copy the saved source using `source_event_id` plus matching `sha256` and a new attachment ID. The copy becomes a new immutable source.

`GET /api/conclave?action=image&conversation=<id>&event=<image-id>` serves authenticated, conversation-scoped PNG/JPEG bytes with private/no-store and nosniff headers. Hosted image reads query the source and latest removal marker in a consistent transaction, without hydrating the engine. Hosted transcripts subtract `image_data` in PostgreSQL before transfer.

Local accounting tokenizes text/framing only and adds an **uncalibrated 4096-unit reserve per image**. It is not exact native image tokenization or a guaranteed provider upper bound. Provider preflight and reported usage remain distinct; source-byte savings calibration excludes image-bearing requests. Native input audit bytes describe compact image references, not wire transfer. Cache-prefix token estimates exclude pixel blocks while logical cache matching retains source identity. No image cost/quality/savings claim is inferred from local reserves.

Validation: `test/images.test.js` covers malformed/oversized input, both native adapters, accounting, immutable requests, source recovery, saved/reloaded follow-ups, old-image selection and signed Claude restart, revision/removal, Agent service restart/Stop, and PGlite hosted retrieval/authentication/isolation. Ordinary Chat, Gemini, OCR extraction, image editing, image memories, multiple images per request, and cross-chat sharing are outside this increment.
